# check in, please — Unity Demo

本目录中的 `UnityDemo` 是 Unity 6.3 LTS（6000.3.28f1）项目。v0.4.6 采用固定侧上方斜俯视的三层实时三维剖顶建筑，最多显示一层建筑，支持 WASD、鼠标移动与靠近交互：一楼前台和办公室电脑，二楼 201–203、三楼 301–303 六间大套房。上下楼采用独立楼梯间过渡：接近平台楼层渐隐，平台只保留人物和楼梯，离开平台楼层渐显，角度和缩放固定。套房包含起居区、卧室、书房和卫浴，隔墙实际限制摄像头与人物视线。

## 启动

双击根目录的 `Play-Demo.cmd`，或运行 `Builds/Windows/CheckInPlease.exe`。后续改动直接更新工程和此运行目录，不再额外生成版本压缩包。请保留同目录中的 `CheckInPlease_Data`、`UnityPlayer.dll` 和其他运行库，不能只复制 exe。

编辑工程：在 Unity Hub 中添加本目录的 `UnityDemo` 文件夹，使用 6000.3.28f1 打开。打开 `Assets/CheckInPlease/Scenes/Hotel.unity` 并点击 Play。如果尚未生成场景，可在菜单 **Check In Please → Create Demo Scene** 创建。

软件位置：
- 编辑器：`F:\CheckInPleaseTools\Unity\6000.3.28f1\Editor\Unity.exe`
- Hub：`F:\CheckInPleaseTools\UnityHub\Unity Hub.exe`
- 安装包与日志：`F:\CheckInPleaseTools\Downloads`、`F:\CheckInPleaseTools\Logs`

Unity 许可证需要通过 Hub 登录并激活。此项目不包含或绕过许可证。

## 可玩流程

1. 晨间阅读新规，支付 20 现金与 2 配给。
2. 走到一楼前台，每日审查三名来客。比较证件与条例，可询问、拒绝，或批准入住并分配到二、三楼的六间客房。
3. 处理完来客后开始夜班。沿西侧楼梯进入二楼或三楼；住客外出统一点名，此时可开门进入客房。
4. 搜查书桌和行李。每夜 4 次行动；同一来源只消耗一次，自动记录线索。查看时切换到平面视角，可翻面。
5. 沿楼梯返回一楼，走到办公室的电脑前，选择同一住客的两个独立来源，点击「电脑提交举报」。仍可封存、销毁或外泄材料。
6. 结束审计进入次日。违规放行的罚款、举报回执和外泄后果会延迟到次日。第三日结束后根据经营状况给出结局。

WASD 按画面方向移动（W 上、S 下、A 左、D 右），也可鼠标点击地面寻路；人物停止后保持最后移动方向。WASD 会取消待执行的鼠标路线；墙壁、家具、关闭的房门与楼层边界会阻挡移动，斜向移动不会加速。J 打开日志，Esc 返回或暂停；界面打开时不能移动或触发场景交互。重要操作及手动移动停止时自动存档。

场景不再常驻显示物品标签。靠近可交互物品时，在各个物品旁悬浮小型按钮，**只显示动作名称**。当前目标按钮较亮，备选按钮较暗；按 **E** 执行当前动作，按 **R** 或鼠标滚轮切换明亮目标，也可直接点击任意按钮执行其动作。按钮不附带物品名称、按键提示或序号，离开范围后隐藏，不会隔墙、穿过关闭的门或远程搜查。

- 前台：开始登记；处理完来客后变为开始夜班。
- 楼梯直接行走通行，不显示交互按钮，也不需要按 E。
- 客房门：开门 / 关门，支持门内外操作。
- 书桌、行李：搜查对应物品，自动识别人物实际靠近的房间。
- 办公室电脑：使用举报电脑。
- 门口监控：安装摄像头 / 调整摄像头，打开独立控制面板。

## 三层建筑与通行

- 楼层主体宽度由 19.2 扩至 30.6，后部深度由 6.6 扩至 10.6，走廊深度由 3.3 扩至 4.2。楼梯连接同步移至扩建后的西侧。
- 一楼：前台、扩大的等候休息区、办公室、电脑与档案区。审查必须走近前台；举报必须走近办公室电脑。大厅与办公室处于同一张可行走的三维楼层。
- 二楼：201、202、203；三楼：301、302、303。两层都能实际分配住客、安装监控、开门搜查和取得证据。每日来客仍为原有三名，不增加经济负担。
- 每层西侧为楼梯间。楼层入口显示连接当前层的半截；走进下半段时显示下半段与楼下，走进上半段时显示上半段与楼上，扶手同步裁切。
- WASD 可直接走上踏步，随时停止、转向和折返；鼠标可以点击踏步、转角平台或当前可见楼层寻路。踏步具有连续高度，栏杆边缘与楼梯中间的空隙不可穿越。
- 接近半层平台时，旧楼层逐渐淡出、连接的另一半楼梯逐渐显现；平台阶段只保留人物与这一连接的两半段，不显示楼层建筑。跨过平台后，新楼层随离开平台逐渐淡入，不叠加两层建筑。
- 镜头角度和缩放固定。仅在楼层完全隐去的楼梯间阶段连续衔接投影高度，人物和楼梯不会在平台中线突然跳动；有楼层显示时保持对应楼层的固定构图。一楼前往三楼仍经过二楼。
- 过渡由人物位置控制，途中停步、暂停、折返及读档都能保持或恢复对应画面；隐去的楼层不能被鼠标点击，楼梯始终可以行走。
- 地图可辅助跨层寻路，途中可随时用 WASD 或另一次地面点击接管。楼梯上松开 WASD 后自动保存实际高度，继续游戏会回到同一位置和视角。
- 人物所在楼层、位置与楼梯上的实际高度随存档保存。旧存档的客房与楼梯坐标会迁移到扩建后的位置；如果落点被新布局挡住，则回到对应客房门外，保留经营进度和观察配置。

## 客房视角与观察

- 沿楼梯到达二楼或三楼后，靠近房门、物品或监控后交互，自动操作对应房间。
- 侧上方固定正交镜头、去屋顶和局部降低的前墙，能同时看到走廊及三个房间。房门可以实际开合。
- 每套客房从 6.4 × 6.6 扩为 10.2 × 10.6，面积约为原来的 2.56 倍。起居区设沙发、茶几和小茶水台，后部为独立卧室、书房与卫浴；内部开放门洞连通，可实际走入各区。书桌搜查点位于书房，行李位于起居区。
- 201 房初始配有一台摄像头。其余房间未安装，所有房门初始关闭。没有有效观察来源时，内部完全遮黑，只保留房间边界和门牌。
- 门口附近按 R 或滚轮切换到监控动作，按 E / 点击打开控制面板；「切换安装位置」「左转 / 右转 15°」「视角」控制对应房间。卧室后角、书房后角、起居室前角三个安装点，以及朝向、视角、距离和隔墙共同决定覆盖范围，摄像头不会揭示整套房。
- 摄像头、人物和门口视线都受内部隔墙限制，门洞处保留柔和过渡。家具不参与视野遮挡；床、书桌等实体仍会挡住人物行走。
- 宵禁后走近房门，按 E 或点击「开门」。可见范围随人物在走廊中的位置变化。进入房间后可直接观察，离开或关门会重新遮黑。
- 摄像头只能观察，搜查仍须开门、走近物品并消耗原有搜查行动。不可见物品不显示交互标签。白天允许查看楼层和调整已有摄像头朝向，开门、安装及移动摄像头需等到夜班。
- 摄像头配置和房门状态随存档保留；旧 v1 存档自动补齐这些设置。当前原型安装摄像头不另收费用，不引入新的经济规则。

存档：`%USERPROFILE%\AppData\LocalLow\Northern District\Check In Please\hotel-save-v1.json`，上一次文件保留为 `.bak`。自动验证模式不会写入玩家存档。

## 工程结构

- `Scripts/Core/GameModel.cs`：独立于 Unity 的状态机、九名住客、证据来源、规则与延迟后果。
- `Scripts/WorldView.cs`：侧上方镜头、实时人物、步行动画及证件肖像。
- `Scripts/WorldView.Hotel.cs`：三层建筑组织、一楼前台及办公室电脑、折返楼梯、楼层通行与住客呈现。
- `Scripts/WorldView.Stairs.cs`：连续楼梯行走面、踏步点击、跨层路径与按位置切换可见楼层。
- `Scripts/Core/StairTransition.cs`：楼梯间淡出、淡入及连续高度衔接规则。
- `Scripts/StoreyTransitionEffect.cs`、`Resources/HotelStoreyBlend.shader`：整层场景与持续显示的人物 / 楼梯画面混合，统一淡出建筑、文字和住客，界面不随场景淡出。
- `Scripts/Core/HotelLayout.cs`：楼层高度、六间有效客房和逐层通行规则。
- `Scripts/Core/SuiteLayout.cs`：套房尺寸与隔墙几何，由建模、行走碰撞、CPU 与 GPU 视线共享。
- `Scripts/WorldView.Suites.cs`：内部房间、门洞、起居与卫浴家具、一楼扩建区域。
- `Scripts/WorldView.Floor.cs`：客房楼层的三维建筑、家具、门、监控模型及世界坐标寻路。
- `Scripts/Core/RoomObservation.cs`：可序列化的观察配置、摄像头视角和门洞视线规则，独立于 Unity 可测试。
- `Scripts/DemoGame.cs`：交互、存读档、场景切换、环境音及自动运行验证。
- `Scripts/DemoGame.Interactions.cs`：附近目标、E / 鼠标触发、R / 滚轮切换、动作提示和监控控制面板。
- `Scripts/DemoUI.cs`：中文 HUD、审查、物品、档案、日志、结局与暂停界面。
- `Resources/HotelMatte.shader`：内置渲染管线的哑光阴影材质。
- `Resources/HotelPlate.shader`、`HotelOverlay.shader`：场景背景与人物接触阴影。
- `Resources/HotelRoom.shader`：实时视野遮黑、软边过渡及旧墙面、木材、织物材质。
- `Resources/HotelText.shader`：带深度遮挡的世界文字，避免上下楼时门牌和招牌穿透楼板。
- `Resources/Art/`：可直接运行的环境和纸张素材，已放入工程，不依赖在线服务。
- `Editor/DemoBuilder.cs`：场景生成与 Windows Mono 构建。

整座旅馆采用实时三维场景，建筑与家具按选定 B 方案重建，固定侧上方视角，不提供自由旋转或搬动家具。当前楼层剖顶显示以避免上层遮住下层，三层建筑和楼梯在同一世界坐标中连接。前台审查保留证件桌面界面，办公室使用电脑举报终端。人物仍为程序建模与简单步行动画。证件上的姓名、编号、规则、线索和处置按钮均为运行时内容。

原概念图保留在 `output/gameplay-concepts-v2-dark`。背景素材来源与生成提示词记录在 `output/runtime-art-v2/manifest.json`；新增墙面、木材、地毯和织物图集使用内置 image_gen 生成，原始提示词与来源记录在 `output/runtime-art-v3/manifest.json`，运行素材为 `Resources/Art/RoomSurfaces.png`。新版实机截图由测试生成到 `Builds/Windows/Validation`。

当前范围不含完整长篇剧情、五阵营系统、自由对话、战斗或正式配音。六个客房复用布局；玩法无联网依赖，代码不接入在线服务。中文默认使用 Windows 系统字体 Microsoft YaHei，未复制分发商业字体。

## 构建与检查

PowerShell 从本目录运行：

```powershell
dotnet run --project Tests/CheckInPlease.ModelTests.csproj
.\Build-Demo.ps1
.\Test-Demo.ps1 -Mode Demo
.\Test-Demo.ps1 -Mode Hotel
```

第一项检查关键经济与流程约束。第二项使用 F 盘编辑器批量创建场景并构建。为避开 Unity Linker 对路径中英文逗号的解析问题，脚本将源工程同步到 `F:\CheckInPleaseTools\BuildWorkspace\UnityDemo`，构建成功后再将成品复制回本目录；不移动源工程。第三项在真实 Unity Player 中走完三天、截图并退出，输出位于 `Builds/Windows/Validation`，退出码 0 表示流程检查通过。它是独立验证模式，不修改正常存档。

第四项专项检查 WASD 方向与速度、碰撞、寻路接管、界面暂停、单层显示、一楼前台、六房分配、楼梯自由升降、途中停止与折返、全程固定镜头、点击平台与踏步、楼梯途中读档、套房分区通路、隔墙的 CPU / GPU 遮黑一致性、跨层视野隔离，以及返回一楼电脑提交举报。原 -floorSmokeTest 参数仍兼容，运行同一套专项检查。构建脚本保留已有 Validation 目录和运行日志。截图按版本和运行时间分别存入 Validation，复测不会覆盖正在预览的图片。

自动检查统一使用 `Test-Demo.ps1`，不带参数时依次执行两套检查。脚本将游戏启动在不激活的独立 Windows 桌面中，保留真实渲染和截图，不向当前桌面弹出窗口或抢焦点；每套默认最多运行 600 秒，完成、失败或超时后释放自己创建的进程和桌面。日志为 `Builds/demo-background-validation.log` 和 `Builds/hotel-background-validation.log`。启动失败不会回退到前台窗口。正常双击 `Play-Demo.cmd` 仍会打开可玩的游戏。

不要直接最小化或隐藏窗口来进行截图验证：本项目这种方式会产生全黑画面。后台检查通过 Windows 的 [CreateDesktop](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-createdesktopw) 隔离窗口，而不是关闭渲染。
